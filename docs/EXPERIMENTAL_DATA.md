# Measured property targets (EXPERIMENT_PLAN §4, class 3)

Module: `src/topoqspr/expdata.py`. Coverage script: `scripts/expdata_coverage.py`
(output `docs/expdata_coverage.json`). Tests: `tests/test_expdata.py`.

This document lists the open datasets of **measured** small-molecule properties that can serve
as headline (class-3) targets, the licence of each, the curation rules applied before any value
reaches a model, and how many approved drugs each one covers. It contains counts only; no model
was fitted. The per-disease counts cover the EXPERIMENT_PLAN candidate list plus the quarantined
pilot (*Migraine Disorders*).

### Known curation issues by source

* **AqSolDB** merges 9 public sets. `SD` is the spread across those sets, and `Group` encodes
  reliability: G1 = 1 occurrence; G3/G5 = 2 / ≥3 occurrences with SD ≤ 0.5; G2/G4 = 2 / ≥3
  occurrences with SD > 0.5 (verified on the file: G2 SD min 0.5001, G3 max 0.500). Temperature
  is not a column; the sources report ≈25 °C. 1,098 records are salts, hydrates or other
  multi-component substances. Inorganics and organometallics are included.
* **Bradley** pools vendor catalogues (Alfa Aesar 8,785 rows), PHYSPROP (9,687 rows, which overlap
  OPERA MP), DrugBank (875), Aldrich and literature. Rows the curators found wrong carry
  `donotuse` (salt, mixture, out of range, wrong isomer, sign inversion). Many rows have
  `csid = 0` (no ChemSpider record). The file does not say which values are decomposition points.
* **OPERA** sets are QSAR-ready: already de-duplicated and stereo-merged by the OPERA workflow.
  Some `Original_SMILES` list several alternative structures separated by `|` (stereoisomers
  merged into one record). These cannot be assigned to one full InChIKey and are excluded as
  `ambiguous_structure`. `WS_QR` reports a temperature for 3,720 of 5,269 records (20–30 °C);
  the rest are blank. `MP_QR` carries no per-record reference. OPERA values are
  pre-aggregated: a record whose `MPID` lists several PHYSPROP IDs (`a|b|c`) merges that many
  PHYSPROP entries (usable records with more than one ID: logP 856, MP 195, WS 2,966). OPERA
  does not publish the spread of a merged value, so the disagreement rule (§2, rule 5) can
  only fire when several OPERA records standardise to one parent. Merged entries may repeat
  one original measurement under several PHYSPROP IDs, so `n_measurements` for OPERA counts
  entries, not necessarily independent measurements.
* **AstraZeneca** compounds are mostly AZ research compounds. The assays have finite ranges
  (logD −1.5 to 4.5; solubility 100 nM to 1,513,600 nM), and values at the limits are stored
  with `=`, so ChEMBL does not mark them as censored. The rule `assay_range` (§2, rule 1)
  marks them `censored_value`: logD 5 records (1 at −1.5, 4 at 4.5), solubility 20 records
  (6 at 100 nM, 14 at 1,513,600 nM).
* **Biogen** compounds are commercially available screening compounds (Enamine, eMolecules,
  WuXi, Mcule), not drugs. Solubility is measured at pH 6.8.

## 2. Curation rules (implemented in `expdata.py`)

Applied to every record. The first failure wins, and nothing is imputed: a record that fails a
rule keeps `value = NaN` plus a `status` code and a `detail` text.

1. **Value.** Missing or non-numeric → `missing_value`. A qualified value (ChEMBL
   `standard_relation` other than `=`) → `censored_value`, and so does a value at or beyond a
   target's assay range (`TargetSpec.assay_range`, tolerance 1e-6; set for `logd74_az`
   [−1.5, 4.5] and `logs74_az` [log10 1e-7, log10 1.5136e-3]). Rows the source marks as bad
   (Bradley `donotuse`, ChEMBL `data_validity_comment`) → `flagged_by_source`. An OPERA record
   with `|`-separated alternative structures → `ambiguous_structure`.
2. **Units.** Values are normalised to log10(mol/L) for solubility, degC for melting point, and
   log10 for logP/logD (`convert_unit`: mol/L, mM, µM, nM, g/L, mg/L, µg/mL and their log forms;
   K and °F to °C). A mass-based concentration is converted with the molar mass of the
   *recorded* structure, which is the form that was weighed. A failed conversion →
   `unit_conversion_failed`.
3. **Structure.** `topoqspr.graph.standardize` on the recorded SMILES (ChEMBL structure
   pipeline parent plus the documented fallback). Its rejection codes are kept unchanged
   (`unparsable`, `disallowed_element`, `no_carbon`, `mixture`, `parent_ambiguous`,
   `too_few_heavy_atoms`, …). No InChIKey → `no_inchikey`.
4. **Solid form.** Solubility and melting point are properties of the solid form that was
   measured. A record whose recorded structure has more than one component (salt, hydrate,
   solvate, co-crystal) is therefore excluded as `salt_or_solvate_form`, even though its parent
   standardises cleanly: the solubility of metformin hydrochloride is not the solubility of
   metformin. logP/logD describe the neutral species in solution, so for them salts collapse onto
   the parent. `keep_salt_forms=True` turns the rule off for a sensitivity analysis.
5. **Aggregation** by the full 27-character InChIKey of the standardised parent:
   * `value` = **median** of the record values;
   * `n_measurements` = number of underlying measurements (an AqSolDB row counts as its
     `Ocurrences`, an OPERA record as its number of distinct `MPID` PHYSPROP IDs);
   * `sd` = the larger of the sample SD (ddof = 1) across records and any SD the source
     reports for a record;
   * `replicates_disagree` = `sd > disagreement_sd`, with **0.5 log units** for logS, logP and
     logD (AqSolDB's own reliability cut-off) and **10 °C** for melting point. These thresholds
     were fixed before any drug coverage was counted.
   * `get_target` drops disagreeing parents by default (`drop_disagreeing=True`). The count
     dropped is in `df.attrs`.

Sources are **not pooled** with each other. Bradley and OPERA MP share PHYSPROP values, and
AqSolDB and OPERA WS share several sets, so pooling would count one measurement twice.

### Interface for the pipeline

```python
from topoqspr.expdata import TARGETS, get_target, load_records
df = get_target("logs_aqsoldb")    # inchikey | value | n_measurements | source | sd | replicates_disagree
df.attrs["unit"]                   # 'log10(mol/L)'
audit = load_records("logs_aqsoldb")   # one row per source record, with status/detail
```

Targets: `logs_aqsoldb`, `logs_opera`, `logs74_az`, `logs68_biogen`, `mp_bradley`, `mp_opera`,
`logp_opera`, `logd74_az`. Downloads are verified against the pinned SHA-256 and stored in
`~/.cache/topoqspr/expdata/<source>/` (or `$TOPOQSPR_CACHE/expdata`). A hash mismatch raises
`ChecksumError`: a bad download is never stored, and a corrupted cached file is never replaced
silently. ChEMBL sources are checked against a SHA-256 of their records pinned per ChEMBL
release. A release without a pin raises, so a new release has to be pinned explicitly.
Processed record tables are cached by raw hash, processing version, RDKit /
structure-pipeline versions and `processing_fingerprint()`: the topoqspr version, the SHA-256
of the `graph.py` and `expdata.py` sources, and the output of the current `standardize` on a
fixed probe panel that exercises every rejection code and parent rule. Any change to the
standardiser therefore invalidates the cache, so target and drug InChIKeys always come from the
same standardiser. The in-process standardisation memo is reset on the same fingerprint. Drugs are matched to targets through the same standardisation:
`standardised_keys(cohort.included)`.

## 5. Recommendation

Criteria fixed in the task: **n ≥ 200** pooled drugs for a confirmatory pooled target, and
**n ≥ 50** per disease for a confirmatory disease × target cell.

1. **Confirmatory pooled targets: four endpoints, one source each.**

   | Endpoint | Confirmatory source | n drugs | Sensitivity source (same endpoint, not in the confirmatory family) |
   |---|---|---|---|
   | Melting point | `mp_bradley` | 711 | `mp_opera` (509) |
   | logP | `logp_opera` | 505 | – |
   | logD7.4 | `logd74_az` | 369 | – |
   | Aqueous solubility (logS) | `logs_aqsoldb` | 351 | `logs_opera` (349) |

   Each endpoint gets exactly one source in the BH family, because the alternative sources
   share underlying measurements (PHYSPROP sits inside both Bradley and OPERA MP, and AqSolDB
   includes the PHYSPROP solubility values). Two sources for one endpoint would be two
   correlated tests of the same hypothesis. Bradley is preferred for melting point because it
   is larger and CC0, and it has an explicit bad-record flag. AqSolDB is preferred for
   solubility because it is CC0, it carries per-record reliability (SD, Group) that the
   disagreement rule uses, and its n is the same as OPERA WS. logP and logD7.4 are distinct
   endpoints: logD includes ionisation, which a graph without element or charge information
   cannot see. Both are kept.

2. **Not confirmatory:** `logs74_az` (84) and `logs68_biogen` (35) are below 200. They are
   exploratory at most. Biogen compounds are screening compounds, so the set adds almost no drugs.

3. **Per disease: no disease × target cell reaches 50** (largest: Hypertension × melting
   point, 47). Under the plan's §7 rule, the per-disease part of the confirmatory family is
   therefore **empty for every class-3 target**. Per-disease measured-target analyses can only
   be descriptive or exploratory. This agrees with the audit's recommendation to model on the
   pooled set (EXPERIMENT_PLAN §8 B already names the pooled set as primary). The plan should
   state it explicitly at freeze.

4. **Rules to freeze with the plan:** full-InChIKey matching (the first-block column is
   informational only); salt and solvate forms excluded for solid-state endpoints; AstraZeneca
   assay-limit values censored; median
   aggregation; disagreement thresholds 0.5 log units and 10 °C with disagreeing parents
   dropped; and the source hashes above (ChEMBL_37 for the AstraZeneca sets). The
   `keep_salt_forms=True` and `drop_disagreeing=False` variants are the pre-specified
   sensitivity analyses.

These counts are drug coverage only. No property value of any drug was inspected or modelled.
